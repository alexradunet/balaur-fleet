# Setup, piece by piece

For a Duet that already runs NixOS (installed with the graphical installer, "erase disk").
Each stage says **what** you do, **why**, and **how to check** it worked. Do them in order
and stop at the first check that fails.

Nothing in stages 0-4 changes your running system. Stage 5 is the first one that does, and
it is reversible (the old system stays in the boot menu).

---

## Stage 0: Look at what you have

The config needs four facts about your install. Run this in a terminal on the Duet:

```bash
whoami
findmnt -no TARGET,SOURCE,FSTYPE /boot /boot/efi
lsblk -f
grep -E 'stateVersion|systemd-boot|grub|efiSysMountPoint' /etc/nixos/configuration.nix
```

| You learn | Why it matters |
|---|---|
| `whoami` (your username) | Becomes `duet.user`. If it is missing from the config, NixOS removes that account on the next rebuild. |
| Where the EFI partition is mounted (`/boot` or `/boot/efi`) | The config uses systemd-boot. If yours is `/boot/efi`, you add one line (stage 3). |
| `stateVersion` | Keep the value your install chose; do not "upgrade" it by hand. |
| Whether `lsblk -f` shows `crypto_LUKS` | A disk-encrypted server waits for a passphrase on every reboot, including after a power cut. Fine for a laptop, awkward for a server. Tell me if you see it. |

## Stage 1: Get git, gh and flakes (temporarily)

A fresh NixOS has none of these set up. This only affects the current shell:

```bash
export NIX_CONFIG="experimental-features = nix-command flakes"
nix-shell -p git gh
```

You are now in a shell that has `git` and the GitHub CLI `gh`.

Log in to GitHub once (the Duet has no browser, so use the device-code flow):

```bash
gh auth login
```

Choose **GitHub.com**, then **HTTPS**, answer **Yes** to "authenticate Git with your GitHub credentials", then **Login with a web browser**. It prints a one-time code and a URL: open the URL on your phone or PC, type the code, approve. Check with `gh auth status`.

## Stage 2: Fetch the config and add *your* hardware file

```bash
gh repo clone alexradunet/yoda-duet-7-home-server
cd yoda-duet-7-home-server
cp /etc/nixos/hardware-configuration.nix hosts/duet/
git add hosts/duet/hardware-configuration.nix
```

- `hardware-configuration.nix` was generated by the installer from your real disks. The repo
  uses it automatically when present.
- `git add` is required: flakes only see files git knows about.

Check: `ls hosts/duet/` shows `hardware-configuration.nix`.

## Stage 3: Edit the one file that is yours

```bash
nano hosts/duet/default.nix
```

Set, using what you learned in stage 0:

```nix
  time.timeZone = "Europe/Bucharest";     # yours
  # system.stateVersion = "26.05";        # uncomment and match your install if it differs

  duet = {
    user = "alex";                        # from `whoami`
  };
```

- **SSH keys are skipped for now**: SSH logs in with your account password (the one you use at the console). Later: put keys in `duet.sshKeys` and set `duet.ssh.passwordAuth = false`.
- If stage 0 showed the EFI partition at `/boot/efi`, also add at the top level of the file:
  `boot.loader.efi.efiSysMountPoint = "/boot/efi";`

Save in nano with Ctrl+O, Enter, Ctrl+X.

## Stage 4: Build it without switching to it

```bash
df -h /                                   # want 15+ GB free
nixos-rebuild build --flake .#duet
```

This evaluates the config and downloads/builds everything (a few GB, mostly Chromium), then stops. It does **not** touch the running system.

Check: it ends without `error:` and leaves a `result` symlink. Errors here are safe; send
me the text.

## Stage 5: Install it for the next boot

```bash
nixos-rebuild boot --flake .#duet --sudo
reboot
```

- `boot` (not `switch`): the new system takes effect only at reboot, so it does not tear
  down the desktop you are sitting in.
- `--sudo`: evaluates as your user (so git is happy) and uses sudo only to activate.
- **Undo**: the systemd-boot menu lists previous generations. Tap Space/arrow keys while it
  appears and pick the older one.

## Stage 6: What you should see

Boot splash, then the dashboard full-screen on the touchscreen. Your old desktop is gone
by design.

| Problem | Do this |
|---|---|
| Black screen / no dashboard | Plug in a keyboard, press Ctrl+Alt+F2, log in, then `journalctl -u cage-tty1 -u duet-dashboard -b` |
| Dashboard tiles all grey | `systemctl status duet-dashboard`; the tile dots are `systemctl is-active` results |
| Can't log in at console | Your old password still works for your old username (`duet.user`) |

## Stage 7: Tailscale and SSH

```bash
sudo tailscale up
```

Open the URL it prints (on any device), approve the machine. Then, from another device on
your tailnet:

```bash
ssh duet            # Tailscale SSH: identity-based, no password needed
ssh alex@duet      # normal sshd over the tailnet: asks for your password
```

LAN SSH works too (password): `ssh alex@duet.local` (or use the IP from `ip -br a`).

## Stage 8: Check the dashboard

From another device: `http://duet.local` (or `http://<the Duet IP>` if `.local` does not
resolve). It lists the running services; for now that is Tailscale. As we add services each
one gets a tile.


## Day to day

```bash
cd ~/yoda-duet-7-home-server
nano hosts/duet/default.nix        # or any module
nixos-rebuild switch --flake .#duet --sudo
git add -A && git commit -m "..."  # the repo is your system's source of truth
```

Optional things you can turn on later (all in `hosts/duet/default.nix`):
`duet.files.enable` (Syncthing). The repo grows as we add services; each one registers its own dashboard tile.

## Stage 9: Code on the Duet

The agent harnesses come from [numtide/llm-agents.nix](https://github.com/numtide/llm-agents.nix)
(updated daily, pre-built in a binary cache), not from nixpkgs, which lags by months:
`claude` (Claude Code) and `pi` ([pi.dev](https://pi.dev)).

**The first rebuild after adding them** should use the numtide cache so nothing compiles on
the Duet. The flake declares the cache, but Nix asks you to accept flake-provided settings
once:

```bash
cd ~/yoda-duet-7-home-server && git pull
nixos-rebuild switch --flake .#duet --sudo --accept-flake-config
```

(After that first switch the cache is part of the system config, so the flag is not needed.)

Then, over SSH, start `herdr` ([herdr.dev](https://herdr.dev)), the terminal workspace manager for agent sessions (`herdr --help` for keys, panes and reattaching), and run the agents inside it:

```bash
herdr
cd ~/yoda-duet-7-home-server
claude                  # first run: follow the login prompt (open the URL on another device)
pi                      # first run: log in or set your provider's API key; see `pi --help`
```

**Updating the agents** (they move fast):

```bash
cd ~/yoda-duet-7-home-server
nix flake update llm-agents
nixos-rebuild switch --flake .#duet --sudo
git add flake.lock && git commit -m "Bump agents"
```

`gh`, `ripgrep`, `fd`, `tree` and Node are installed system-wide. Per-project compilers and
toolchains should come from each project's own `nix develop` shell instead of system packages.
